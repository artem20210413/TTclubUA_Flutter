# Quickstart: Екран мапи з учасниками по містах

Гайд для ручної перевірки (автоматизованого widget/integration тест-набору для подібного екрана поки немає — див. `plan.md`, розділ "Технічний контекст" / `research.md` §5–8).

## Передумови

- Flutter SDK, що відповідає `pubspec.yaml` (`^3.5.4`).
- Нові залежності додано до `pubspec.yaml` та завантажено: `apple_maps_flutter`, `flutter_map`, `latlong2`, `geolocator`, `cached_network_image` (див. `research.md` §1, 3, 4).
- iOS: `NSLocationWhenInUseUsageDescription` додано в `ios/Runner/Info.plist`.
- Android: `ACCESS_FINE_LOCATION`/`ACCESS_COARSE_LOCATION` додано в `android/app/src/main/AndroidManifest.xml`.
- Backend/тестове середовище, доступне застосунку, яке віддає `GET api/cities/map` та `GET api/cities/{id}/users` за `contracts/cities-map-api.md`, з щонайменше одним містом з `users_count == 1` та аватаркою, одним з `users_count > 1`, та одним учасником з відсутньою/зламаною аватаркою (для перевірки всіх станів мітки/запасного варіанту).

## Налаштування

```bash
flutter pub get
flutter run   # або: flutter run -d <ios-simulator-id> / -d <android-emulator-id>
```

Перейти на новий екран мапи учасників по містах звідти, куди його підключено в навігації застосунку (див. фактичну точку входу в `tasks.md`).

## Сценарії перевірки

1. **Дозвіл на геолокацію надано**: При першому відкритті прийняти запит дозволу на геолокацію. Очікується: камера центрується на замоканому поточному місцезнаходженні симулятора/емулятора із зумом 6.0 (див. інструменти платформи для встановлення кастомної локації).
2. **Дозвіл на геолокацію відхилено**: Відхилити запит (або запустити з вимкненими службами локації). Очікується: камера центрується на Києві (50.4501, 30.5234) із зумом 6.0.
3. **Місто з одним учасником та аватаркою**: Знайти/замокати місто з `users_count == 1` та робочим URL `avatar`. Очікується: мітка показує аватарку цього учасника в колі.
4. **Запасний варіант при зламаній аватарці**: Замокати місто з `users_count == 1` та URL аватарки, що повертає 404. Очікується: мітка показує стандартний стилізований кружок з "1".
5. **Місто з кількома учасниками**: Знайти/замокати місто з `users_count > 1`. Очікується: мітка показує фірмовий бейдж з кількістю.
6. **Помилка завантаження даних мапи**: Змоделювати помилку мережі для `GET api/cities/map` (напр. авіарежим перед першим завантаженням). Очікується: з'являється ненав'язливий SnackBar з повтором; тап на "Повторити" повторює спробу завантаження; мапа лишається видимою/керованою під ним.
7. **Відкриття списку учасників**: Тапнути на мітку з `users_count >= 1`. Очікується: відкривається модальна шторка з заголовком (назва міста + загальна кількість), потім стан завантаження, потім перша сторінка рядків учасників (аватарка, ім'я, невеликі другорядні дані).
8. **Нескінченна прокрутка**: У місті з більшою кількістю учасників, ніж на одній сторінці, прокрутити список шторки до кінця. Очікується: наступна сторінка завантажується та додається автоматично, без ручного тапу "завантажити ще".
9. **Помилка завантаження списку учасників**: Змоделювати помилку мережі під час завантаження сторінки. Очікується: ненав'язливий SnackBar з повтором у межах шторки; наявні рядки лишаються видимими; "Повторити" повторює спробу для цієї сторінки.
10. **Перехід з рядка на профіль**: Тапнути на рядок учасника у шторці. Очікується: застосунок переходить на наявний екран `Profile` (`lib/pages/Nav/Mention/Profile.dart`) для `id` цього учасника.
11. **Кешування аватарок**: Закрити та знову відкрити шторку того ж міста (або повернутись до мапи) в межах тієї ж сесії. Очікується: раніше завантажені аватарки відображаються миттєво, без помітного повторного завантаження/мерехтіння.
12. **Нативні кнопки зуму**: Тапнути на кнопку "+" на екрані; камера наближається на один нативний крок. Тапнути на "−"; камера віддаляється на один нативний крок.
13. **Кнопка "моя локація"**: Тапнути на кнопку "моя локація". Очікується: камера анімовано переміщується до поточного місцезнаходження пристрою. За недоступного дозволу на геолокацію очікується: дозвіл (повторно) запитується або показується ненав'язливе повідомлення; застосунок не крашиться і не зависає.
14. **Паритет між платформами**: Повторити сценарії 3–5 та 12–13 на симуляторі iOS (Apple Maps) та емуляторі Android (flutter_map/OSM). Очікується: візуал міток та поведінка кнопок керування еквівалентні, попри різні мап-рушії під капотом.

## Успіх

Усі 14 сценаріїв поводяться, як описано, на обох платформах (iOS та Android) без збоїв та відповідають сценаріям приймання у `spec.md`.
