# Завдання: Екран мапи з учасниками по містах

**Вхідні дані**: Проєктна документація з `/specs/001-city-users-map/`

**Передумови**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md (усі наявні)

**Тести**: Не запитані у специфікації функції; завдання на тести не включені. Перевірка виконується вручну через `quickstart.md`.

**Організація**: Завдання згруповані за user story для незалежної реалізації та тестування кожної історії. Примітка: `lib/pages/Nav/Map/CityUsersMapScreen.dart` вже існує як заглушка екрана (підключена до банера "TTclubUA у світі" на `lib/pages/Nav/Home.dart`); завдання нижче замінюють/розширюють цю заглушку, а не створюють її з нуля.

## Формат: `[ID] [P?] [Story] Опис`

- **[P]**: Можна виконувати паралельно (різні файли, без залежностей)
- **[Story]**: До якої user story належить завдання (US1, US2, US3, US4)
- Вказувати точні шляхи до файлів в описах

## Залежності та порядок виконання

### Залежності фаз

- **Налаштування (Фаза 1)**: Без залежностей — можна починати одразу
- **Базова (Фаза 2)**: Залежить від завершення Налаштування — БЛОКУЄ всі user stories
- **User Story 1 (Фаза 3)**: Залежить від Базової — без залежності від інших історій
- **User Story 3 (Фаза 4)**: Залежить від Базової; залежить від поверхні тапу на мітку з User Story 1 (T010/T011), щоб приєднати шторку, але робота над DTO/сервісом/віджетом (T014–T016) може виконуватись паралельно з US1
- **User Story 2 (Фаза 5)**: Залежить лише від Базової — незалежно тестована, не потребує US1 чи US3
- **User Story 4 (Фаза 6)**: Залежить від Базової лише для кнопок зуму (T025–T026); кнопки "моя локація" (T027–T029) використовують логіку визначення локації з US2 (T022), але коректно деградують, якщо US2 ще не реалізовано (одразу запитують дозвіл)
- **Полірування (Фінальна фаза)**: Залежить від завершення всіх бажаних user stories

### Залежності user stories

- **US1 (P1)**: Лише Базова
- **US3 (P1)**: Базова + приєднується до обробника тапу на мітку з US1 (T010/T011)
- **US2 (P2)**: Лише Базова
- **US4 (P2)**: Базова; кнопки "моя локація" м'яко залежать від логіки локації US2

- DTO перед функціями сервісу, перед віджетами, перед підключенням до екрана

- Історія завершена перед переходом до наступного пріоритету (рекомендований порядок: US1 → US3 → US2 → US4)

- T005 та T006 (базові екрани iOS/Android) паралельно

- T017 та T018 (підключення шторки на платформах) паралельно
- T025–T028 (кнопки зуму/моєї локації на платформах) паралельно

## Стратегія реалізації

### Спочатку MVP (User Stories 1 + 3)

1. Завершити Фазу 1: Налаштування
2. Завершити Фазу 2: Базова (КРИТИЧНО — блокує всі історії)
3. Завершити Фазу 3: User Story 1 (мітки)
4. Завершити Фазу 4: User Story 3 (шторка + перехід на профіль)
5. **ЗУПИНИТИСЬ ТА ПЕРЕВІРИТИ**: Виконати сценарії 3–11 з `quickstart.md` на обох платформах
6. Деплой/демо, якщо готово — це основна цінність за `spec.md`

### Поетапна доставка

1. Налаштування + Базова → порожній екран мапи живий на обох платформах
2. Додати US1 → мітки рендеряться → перевірити незалежно
3. Додати US3 → список учасників + перехід на профіль → перевірити незалежно → MVP готовий
4. Додати US2 → персоналізована початкова камера → перевірити незалежно
5. Додати US4 → кнопки зуму/моєї локації → перевірити незалежно
6. Полірування → прохід quickstart на обох платформах

### Стратегія для команди

З кількома розробниками, після завершення Базової фази:

- Розробник A: US1 (мітки) → потім кнопки зуму з US4
- Розробник B: US3 (шторка), одразу починаючи роботу над DTO/сервісом/віджетом, підключення до міток після готовності поверхні тапу з US1
- Розробник C: US2 (геолокація), незалежно від A/B
